# Davis 晚霞指数 · Davis Sunset Index

每天傍晚为 **Davis, CA (38.5449°N, 121.7405°W)** 生成一份晚霞预报：0–10 分的指数、日落时间与方位角、因子拆解表、峰值时间窗和观测点建议。

由 Claude Code 的定时任务 `davis-sunset-index` 每天 18:30 (PT) 自动运行并推送到本仓库。方法说明见 [METHOD.md](METHOD.md)。

## 方法一句话版

不是简单读云量，而是：**三层云量 + 200–300 hPa 湿度判卷云厚薄 + 沿日落方位角向西 100/220/350 km 查「进光通道」 + 气溶胶 + ECMWF/GFS/ICON 三模式交叉验证**，再按权重打分。

核心洞察是「进光通道」：晚霞要好看，光必须能贴着地平线从西边钻进来打亮头顶的云底。所以西侧上游 100 km（Coast Range 一带）的低云和中云必须接近 0，否则天上云再漂亮也点不着。沿海的海雾（低云 100%）通常不致命——日落时光线经过海岸上空已在 1–2 km 高度，高于 300–600 m 的雾顶。

数据源全部是 [open-meteo](https://open-meteo.com) 的免费 API（forecast + air-quality），无需 key。

## 已知的坑

- **18:30 这个触发时间只在 4–9 月成立**（日落 19:27–20:34）。10 月中旬起日落早于 18:30，冬令时后更是 17:00 左右。任务里写了自检：日落已过或不足 40 分钟就不出预报，改为提示换时间。
- 任务只在 Claude 桌面端开着的时候跑；关着会在下次启动时补跑——历史里 8/18、8/20 的缺口和几次「上午才播报」就是这么来的。
- **不确定性几乎全部集中在「画布」项**。三家模式对低云的判断基本永远一致（进光通道算得准），但对中/高云量能差 3 倍以上。分数的误差条应该几乎全挂在云量项上。

## 站点部分

站点使用 React 19 + Tailwind 4，并通过 GitHub Actions 自动部署到 [GitHub Pages](https://cubhe.github.io/davis_sunset/)。每次 Claude 向 `main` 分支新增 `reports/*.md`，Actions 都会重新生成静态页面，把最新日期放到首页，旧播报自动进入存档，不需要手动改网页代码。

首页采用固定天空背景和滚动驱动的日落动画：向下滑动时太阳落向地平线，天空逐渐从日光过渡为晚霞。太阳落下后，天空定格，第一张圆角「纸」从下方升起盖住它；之后的天空继续从余晖转入星夜，判断依据与往日记录两张纸之间留出一扇透明的夜空「天窗」放置出行计划，页脚停在夜空里收尾。整页只有一片天空，所有幕间过渡都由同一套「纸浮在天上」的语言完成。系统开启“减少动态效果”时会自动显示静态版本。

```bash
npm install
npm run dev
npm run build:pages
```

`npm run dev` 用于本地预览完整站点；`npm run build:pages` 生成 GitHub Pages 使用的 `pages-dist/`。要求 Node ≥ 22.13。
